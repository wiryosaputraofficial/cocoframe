# Decision Log: Coco Doctor

| Decision | Area | Status | Value |
| --- | --- | --- | --- |
| `objective` | intent | answered | Add a read-only cocoframe doctor command that helps developers, CI, and AI clients quickly diagnose CocoFrame project, dependency, configuration, generated-artifact, security, build, and environment problems through actionable human output and a stable machine-readable JSON contract. |
| `actors` | users | answered | ["Application developers running local diagnostics","CI pipelines evaluating project health","AI clients consuming machine-readable diagnostics"] |
| `success-outcome` | intent | answered | One command identifies actionable CocoFrame project problems with stable diagnostic codes, safe evidence, remediation guidance, documentation references, and consistent exit status without exposing secrets. |
| `happy-path` | flow | answered | ["User runs cocoframe doctor in a project","Doctor resolves the project root and environment","Doctor runs safe read-only checks","Doctor aggregates and deterministically orders diagnostics","Doctor renders human output or a versioned JSON document","Doctor exits with a status derived from the result"] |
| `acceptance-criteria` | quality | answered | ["Given a healthy project, when doctor runs, then it exits 0 with no error diagnostics","Given one or more error diagnostics, when doctor completes, then it exits 1","Given an internal doctor failure, then it exits 2 with a sanitized failure","Given --json, output is a versioned contract with no interleaved human logs","Default checks do not modify files, perform network requests, or reveal secrets","Every diagnostic includes code, severity, category, message, sanitized evidence, suggestion, and documentation reference","Expensive checks run only when --deep is explicitly selected","CLI, CI, and Agent Bridge consume the same diagnostic engine and contract"] |
| `entry-points` | flow | answered | ["Terminal from the project root through cocoframe doctor","An explicit project through cocoframe doctor <path>","CI through cocoframe doctor --json","Agent Bridge through the read-only project.doctor tool"] |
| `alternate-paths` | flow | answered | ["--json emits machine-readable output","--deep enables build and other expensive validation","--strict makes warnings produce exit status 1","Without --strict warning-only results exit 0","A healthy project emits a concise passed-check summary"] |
| `error-states` | flow | answered | ["A non-CocoFrame directory reports PROJECT_NOT_FOUND with recovery guidance","Configuration load failures identify the related file without exposing sensitive values","Missing or incompatible dependencies produce dependency diagnostics","Stale generated artifacts include the appropriate regeneration command","Unreadable files produce sanitized diagnostics without including sensitive content","A failed or timed-out deep check produces a check-specific diagnostic","An unexpected doctor failure exits 2 and --json still emits a valid sanitized JSON document"] |
| `out-of-scope` | intent | answered | ["Automatic file repair or mutation","Installing or updating dependencies","Network requests or checks against external services","Running migrations or accessing application databases","Executing arbitrary shell commands","Deploying or publishing applications or packages","Replacing the complete test, typecheck, or security-audit suites"] |
| `existing-capabilities` | intent | answered | ["Reuse inspectProjectReadOnly for a no-build project snapshot","Reuse discoverRoutes, discoverIslands, discoverStyles, discoverGlobalStyles, discoverUiComponents, and discoverIcons","Reuse the canonical routePatternFromFile parser","Reuse generated capability discovery for OpenAPI, clients, API reference, context, assets, and deployment manifests","Reuse Agent Bridge workspace confinement, cancellation, and diagnostic sanitization","Deep build validation uses the canonical build pipeline only in an isolated temporary workspace so the user project remains unchanged"] |
| `ui-states` | interface | answered | ["Initial argument and project-root validation","Running checks without a required spinner","Healthy result with no errors or warnings","Warning result with exit behavior controlled by --strict","Actionable error result with exit 1","Sanitized internal failure with exit 2","Invalid flag or path with concise usage guidance","Disabled state is not applicable because this is a command-line interface"] |
| `accessibility` | interface | answered | ["Do not distinguish information by color alone","Support NO_COLOR and non-TTY output","Avoid mandatory animation or spinners","Use consistent textual ordering for headings, diagnostics, and summary","Write every severity and diagnostic code explicitly","JSON output contains no ANSI escape sequences","Human output remains understandable when copied as plain text"] |
| `responsive` | interface | answered | Human output uses no fixed-width tables, wraps long paths and suggestions safely, and remains vertically readable in narrow terminals; JSON output is independent of terminal dimensions. |
| `persistence` | data | answered | none |
| `integrations` | integration | answered | ["Read-only project filesystem access","Local package.json and dependency metadata","Canonical CocoFrame discovery and inspection engine","Canonical build pipeline in a temporary workspace for --deep","In-process Agent Bridge consumption with AbortSignal cancellation","No external providers or network requests","File and parsing failures become targeted diagnostics","A deep-check failure or timeout does not prevent independent checks from completing","Cancellation stops work promptly and returns a sanitized status"] |
| `security-requirements` | quality | answered | ["Rely on local operating-system permissions; no application authentication is required","Resolve and confine the project root safely","Do not follow symlinks to read outside the workspace","Default checks do not execute project source or configuration","Deep build does not import or execute the application bundle","Render project files as relative paths","Never output environment values, cookies, tokens, authorization headers, passwords, private keys, or sensitive file contents","Bound the size and number of files read","Agent Bridge remains read-only and enforces cancellation and workspace confinement","Collect no automatic telemetry"] |
| `observability` | quality | answered | ["JSON records mode and counts for checks, passed, warning, error, skipped, and internal failure","Every check has a stable ID and status","Diagnostics are deterministically ordered","CI uses exit status and JSON as evidence","No event is transmitted or persisted outside the process","Default output omits timing so snapshots remain stable; doctor performance is measured by separate tests or benchmarks","Unexpected failures expose a stable sanitized code suitable for user reports"] |
| `performance` | quality | answered | ["Default doctor completes within 2 seconds on the reference project without running a build","--deep has a default timeout of 60 seconds","Cancellation is checked between every check and major filesystem operation","At most 10000 files are inspected per run","Source files are limited to 1 MiB per file","At most 1000 diagnostics are returned and the result sets truncated true when the limit is reached","Filesystem operations use bounded concurrency","JSON output never embeds full source files or other large payloads","No browser-performance limit applies because the feature is CLI-only"] |
| `rollout` | delivery | answered | ["Release as an additive command without migration or feature flag","Release the doctor engine, CLI command, and Agent Bridge project.doctor tool in one coordinated package release","Start the JSON contract at version 1","Additive fields remain backward compatible; breaking changes increment the contract version","Never repurpose or silently change the meaning of a stable diagnostic code","The Agent Bridge tool is additive and read-only","Upgrading does not change project source or generated artifacts","Rollback uses the previous coordinated package release","Every release includes documentation, changelog, focused tests, and package smoke verification"] |
