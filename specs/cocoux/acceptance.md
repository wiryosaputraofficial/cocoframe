# Acceptance Criteria: CocoUX

- [ ] Given the same canonical inputs, generated outputs are deterministic, versioned, and machine-readable.
- [ ] Every journey has no dead end and every transition declares a trigger and outcome.
- [ ] Initial, loading, empty, success, validation, disabled, error, offline, and permission states are reviewed.
- [ ] Every interaction declares trigger, target, feedback, keyboard behavior, and recovery.
- [ ] Visual recommendations reuse existing components and design tokens before proposing additions.
- [ ] CocoUX renders a real development-only website preview and captures PNG evidence for approved viewports, themes, and states.
- [ ] Every screenshot records its viewport, theme, state, revision, source hash, and linked UX contract.
- [ ] CocoUX approval permits only handoff of the approved visual direction to CocoRef and never promotes application source.
- [ ] CocoRef receives the approved screenshots and linked UX contract, then retains inventory audit, missing-component consent, exact-preview approval, and source promotion ownership.
- [ ] Temporary CocoUX preview files are removed after successful handoff or cancellation.
- [ ] When an external visual reference exists, CocoRef remains the source of fidelity decisions.
- [ ] CocoQA can derive traceable cases from approved CocoUX and completed CocoRef.
- [ ] CLI and Agent Bridge use the same CocoUX engine and contract.
